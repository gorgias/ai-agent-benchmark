# Minimal AI customer discovery — 2026-10-22

## Scope and method

The [Minimal AI case-study index](https://gominimal.ai/case-studies) lists nine customer stories. This inventory separates the vendor's published customer attribution from evidence that a particular public storefront currently exposes a Minimal-operated chat. Customer status alone is insufficient to attribute a Gorgias, Twini, Zendesk, or other widget's responses to Minimal.

Checks used ordinary public URLs, fresh HTTP requests with a desktop Chrome user agent, the raw served HTML, selected linked JavaScript, and the public widget embed-config endpoint used by Minimal's own loader. Embed-config requests included the actual storefront Origin and Referer. Read-only ordinary browser sessions then inspected Proforto and Hang Eleven to resolve gaps in the static HTML evidence. No chat messages, accounts, orders, or authenticated customer data were used during discovery. Configuration availability is not proof of a successful live conversation.

The native public loader signatures are `https://storefront.gominimal.ai/storefront-widget.js` and the routing loader `https://gominimal.ai/storefront-widget.js`. The former creates an iframe whose ID begins `minimal-storefront-widget-frame-` and whose URL begins `https://storefront.gominimal.ai/storefront-widget/frame`. A loader coexisting with Gorgias is not evidence that the Gorgias widget is operated by Minimal; captures must drive the native Minimal iframe specifically.

## Hang Eleven routing inspection

The inline loader calls its `load()` function only once `kop-minimal-live` is present. The explicit class-setting branch checks `kop_minimal=1` in the URL or `kop_minimal_preview=1` in a cookie, and adds both `kop-minimal-live` and `kop-minimal-preview`. A MutationObserver can also load Minimal if another script later adds the class. Neither the ordinary served HTML, the linked `theme.js`, nor the linked `twini.v2.js` inspected during discovery supplied another Minimal activation path. Static inspection therefore initially left production routing unverified.

The ordinary browser visit resolved that uncertainty: at `https://hang-eleven.com/`, the page acquired `kop-minimal-live kop-satc-live kop-sw-live`, loaded Minimal's frame/config with HTTP 200, and displayed its native `Open chat` launcher. The Twini element was hidden. No preview flags or cookies were set, and checks confirmed no `kop_minimal` query parameter, no `kop_minimal_preview=1` cookie, and no `kop-minimal-preview` class. This supports normal production attribution for the observed session, despite the static loader's preview branch. The exact runtime class setter was not identified.

A capture must record the actual selected widget in its fresh session. If Twini is selected, its answers must not be labeled Minimal merely because the company is a Minimal customer.

1. **Cloudpillo, `https://cloudpillo.com/nl-nl`** — ordinary native Minimal script and enabled public configuration confirmed; attempt both lanes with the native iframe.
2. **Proforto, `https://proforto.nl/`** — ordinary native Minimal frame, HTTP 200 runtime/config, and visible launcher confirmed; attempt both lanes with the native iframe.
3. **Hang Eleven, `https://hang-eleven.com/`** — ordinary session selected native Minimal with HTTP 200 frame/config and visible launcher, without preview activation; attempt both lanes and verify actual routing for every cold session.
4. **Boombrush, `https://boombrush.com/`** — ordinary loader confirmed; the public routing decision selects AWS, whose config reports unavailable. Confirm the resulting visible state in an ordinary session before finalizing the non-measurable status.
5. **Dreaver, `https://dreaver.nl/`** — native loader confirmed but disabled config observed. Record a non-measurable deployment if an ordinary browser confirms that state; do not score an unavailable chat as failed support.

Cloudpillo, Proforto, and Hang Eleven have positive current evidence for an ordinary native Minimal deployment. Dreaver and Boombrush remain availability investigations. Preserve unavailable, unverified, and off-channel customers in the evidence record without assigning invented benchmark scores. Discovery did not send any live chat messages; benchmark capture and judging remain separate subsequent steps.

## Capture outcomes

The retained benchmark attempts were captured on 22 October 2026: one shopping and one support attempt on each of five storefronts, ten cold attempts in total. **None produced a valid benchmark conversation or a timed AI answer. Minimal AI remains unranked, with no quality, automation, or latency score.** These are availability and capture limits, not evidence about the quality of answers the agent would have given.

The [ten raw attempts](../runner/results/2026-10-22/conv/) retain errors, unsent turns, timestamps, and capture provenance. Four attempts reached a first typed question and then the native unavailable state; the other six stopped during startup. Remaining standard themes and guardrails were not sent after these failures. An earlier one-question Cloudpillo return-policy diagnostic received a substantive answer, but one answer does not satisfy the benchmark's minimum of three timed answers, so it was not scored.

Cloudpillo was also checked with [authentic headed Chrome](../runner/results/2026-10-22/diagnostics/minimal-cloudpillo-native-headed.json) and [native headless Chrome](../runner/results/2026-10-22/diagnostics/minimal-cloudpillo-native-headless.json). Both received HTTP 200 for embed configuration and bootstrap exchange, but no session redemption or message request followed. The served widget code places invisible browser verification between exchange and redemption. Verification not completing is the suspected blocker; the evidence does not establish an API, CORS, or AI-quality failure. The same unavailable screen on other stores does not independently prove its cause.

No preview flags, real identifiers, credentials, quick-reply chips, or challenge bypasses were used. Preliminary driver-debugging outputs remain separate from these retained attempts. Unavailable-state metadata is excluded before automation, latency, cached quality, and blind-judge packing, including a session that becomes unavailable after earlier valid answers. With no valid conversations, quality judging and an agreement audit are not applicable; no scores or audit agreement were invented.

After public session verification works, resume the standard five themes in each lane on the three verified production routes and judge the valid conversations through the existing blind pipeline.
